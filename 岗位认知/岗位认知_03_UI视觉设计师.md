# 岗位认知｜UI视觉设计师（Visual / UI）

> **定位**：决定界面长什么样，是否清晰、可信、有品牌感。  
> **核心职责**：对视觉层级、风格一致性与界面品质负责。  
> **协作对象**：产品经理、交互设计师、研发、品牌/市场。

---

## 1. 这个岗位到底做什么

UI视觉设计师管的是「感知与表达」，重点是用户第一眼是否看得懂、信得过、愿意继续操作。

深入看，日常工作通常覆盖：

- **视觉层级**：先看什么、后看什么，重点操作是否足够醒目
- **风格与品牌**：色彩、字体、图标、插画、氛围是否统一
- **组件细节**：间距、圆角、描边、阴影、对齐、控件样式
- **一致性**：不同页面像同一套产品，而不是拼凑
- **可读性与品质感**：字号字重、对比度、留白、细节完成度

常见产出：

- 高保真界面设计稿
- 设计规范 / UI Kit / 组件库
- 图标与视觉元素
- 标注说明与交付切图（或开发可用标注）
- 视觉提案（风格方向、改版对比）

**能力重心**：审美、排版、色彩、品牌表达、落地精度。  
**不是重点**：单独拍板业务优先级，或独自定义复杂业务规则。

一句话：**让产品看起来专业、好认、愿意用。**

---

## 2. 与相邻岗位的边界

以「电商下单」为例：

| 角色 | 关注点 |
|------|--------|
| 产品经理 | 要不要做「一键下单」？目标是提升转化还是提升客单价？ |
| 交互设计师 | 地址、优惠券、支付方式怎么排；缺货/支付失败怎么走 |
| 视觉设计师 | 价格是否突出、主按钮是否够强、页面是否干净可信 |

协作关系：

- 产品定义目标与业务约束
- 交互提供结构、流程与状态
- 视觉在既定结构上完成层级强化、风格统一、品质提升
- 研发按规范实现视觉效果，并反馈可实现性

注意边界：

- 结构混乱，不应只靠“换个好看配色”解决
- 视觉可以反推层级与强调，但不应擅自改业务规则
- 好的视觉是服务任务完成，不是单纯装饰

## 3. 能力模型

### 3.1 必备能力

1. **视觉层级**  
   能通过大小、对比、位置、留白，让用户先看到该看的。

2. **排版能力**  
   能处理好标题、正文、辅助信息的节奏与可读性。

3. **色彩与材质表达**  
   能建立稳定的颜色体系，并控制氛围、状态色、可访问对比度。

4. **组件与一致性**  
   能把按钮、表单、卡片、导航等做成可复用、可扩展的系统。

5. **落地能力**  
   能输出研发可实现的规范，而不是只停留在效果图审美。

### 3.2 进阶能力

- 品牌视觉转产品界面的能力
- 设计系统建设（token、组件、规则）
- 多端适配（移动端 / Web / 深浅色）
- 动效服务于反馈与层级，而不是炫技
- 与前端协作理解（布局限制、性能、实现成本）

### 3.3 常见短板

- 画面好看，但主次不清，用户不知道点哪里
- 单页精致，多页风格漂移
- 只做默认态，不管禁用、报错、空态
- 规范缺失，导致开发还原度差、后续难维护
- 装饰过多，伤害信息密度与操作效率

## 4. 作品集要求（求职/转岗）

视觉作品集要证明：你不只会“做漂亮”，还能让界面更清晰、更统一、更可落地。

每个案例建议包含：

1. **项目背景与目标**（提升信任、转化、品牌感、可读性等）  
2. **设计前问题**（原界面哪里弱：脏、乱、弱、旧、无层级）  
3. **视觉策略**（风格关键词、色彩/字体/组件原则）  
4. **关键界面高保真**（完整链路，不只 Banner）  
5. **规范沉淀**（颜色、字体、间距、组件状态）  
6. **对比说明**（改前改后，强调层级与一致性提升）  
7. **落地结果**（还原度、上线反馈、业务指标，有则写）

建议准备 **2～3 个完整案例**：

- 至少 1 个完整产品界面链路（不是单张海报）
- 至少展示组件多状态（正常/悬停/禁用/报错等）
- 至少有一套可复用的基础规范

评审方最想看到的不是“风格很潮”，而是：

**信息是否更清楚，品牌是否更统一，开发是否更容易稳定还原。**

## 5. 入门学习路径

### 阶段 A：建立基本功（2～4 周）

- 练排版：对齐、间距、字号层级
- 练色彩：主色、中性色、状态色、对比度
- 临摹优质 App/Web 界面，先还原再理解原理

### 阶段 B：形成系统感（1～2 个月）

- 把单页练习升级成多页统一风格
- 建立最小 UI Kit：按钮、输入框、列表、导航、弹窗
- 练习“同一结构，不同风格”和“同一风格，不同业务”

### 阶段 C：能独立交付（持续）

- 独立完成高保真 + 规范 + 研发交付
- 学会基于交互稿做视觉强化，而不是重画一套结构
- 通过真实还原问题反推自己的规范是否够清晰

### 阶段建议产出

- 1 套基础设计规范（色板、字体、间距、组件）
- 2 个多页面高保真项目
- 1 份改前改后对比案例（讲清层级与一致性提升）

## 6. 入门需要的基础知识与技能

入门目标是：能做出主次清楚、风格统一、可交付研发的界面，而不是只会画单张漂亮海报。

### 6.1 基础知识

| 类别 | 要掌握到什么程度 |
|------|------------------|
| 造型基础 | 懂对齐、对比、重复、亲密性；懂点线面与基础构图 |
| 色彩基础 | 懂主色/中性色/状态色；懂对比度与可读性 |
| 字体排版 | 懂字号层级、字重、行高、段落节奏、中西文混排基本规则 |
| 布局与栅格 | 懂间距系统、栅格、响应大致规则（至少移动端+Web 基础） |
| 组件认知 | 懂按钮、表单、列表、导航、弹窗、卡片等常见控件 |
| 状态视觉 | 懂默认/悬停/按下/禁用/报错/成功的视觉差异 |
| 品牌与风格 | 懂如何把关键词转成色彩、字体、材质、插画语言 |
| 交付常识 | 懂标注、切图或开发标注；懂还原沟通 |

### 6.2 入门技能清单

- **视觉层级控制**：先看什么、后看什么，一眼能找到主操作
- **排版落地**：标题/正文/辅助信息不打架
- **配色落地**：能搭一套可用色板，不只靠“好看”
- **多页一致性**：同一产品多页面风格统一
- **组件化思维**：重复元素提炼成可复用样式
- **高保真输出**：完整链路界面，不只 Banner 和首页
- **基础工具**：Figma（主工具）；必要时掌握基础图标绘制；会导出/标注给研发

### 6.3 入门必读书（先读完再谈进阶）

入门阶段只要求读透下面这些，不求多。

| 优先级 | 书名 | 作者 | 为什么必读 | 怎么读 |
|--------|------|------|------------|--------|
| 必读 1 | 《写给大家看的设计书》 | Robin Williams | 最快建立排版四原则：对比、重复、对齐、亲密性 | 通读后立刻改自己的界面 |
| 必读 2 | 《配色设计原理》 | 奥博斯科编辑部 | 系统理解色彩关系与应用 | 精读，搭出 1 套可用色板 |
| 必读 3 | 《西文字体》或同类字体入门书 | 小林章 等 | 建立字体选择与文字层级品味 | 边做界面边查，不硬背 |
| 必读 4 | 《设计心理学》 | Don Norman | 避免“好看但不好用” | 精读，检查主操作是否够清楚 |
| 选读 | 《界面设计模式》 | Jenifer Tidwell | 把视觉落到真实组件与场景 | 入门项目进行中当手册查 |

**入门最低标准**：前 4 本读完，并能交付「多页面高保真 + 基础色板字体间距规范 + 组件多状态」。

### 6.4 入门必会工具

| 用途 | 工具 | 入门要会什么 |
|------|------|--------------|
| 界面设计 | Figma | 高保真、组件、自动布局、标注/交付 |
| 图标 | Figma / 基础矢量能力 | 做简单线性图标，保持一致性 |
| 参考管理 | 浏览器收藏 / 灵感板 | 收集可上线产品，不只海报 |
| 协作交付 | Figma 链接 + 飞书/语雀 | 说明规范、状态、还原注意事项 |
| 辅助 | 取色/对比度检查工具 | 保证可读性与可访问对比度 |

### 6.5 入门必看资源（非书）

- Material Design、Apple HIG（先看颜色、字体、组件状态）
- Ant Design / Element 等组件库视觉与状态规范
- 3～5 个高质量上线产品（不是只看 Dribbble 概念稿）
- 基础可访问性：文字对比度、点击热区、状态可见性

### 6.6 入门必做练习

1. 临摹 10 个优质界面，并写“层级为什么成立”  
2. 搭 1 套最小 UI Kit：色板、字体、间距、按钮、表单、列表  
3. 做 1 个多页面高保真项目（含禁用/报错/空态）  
4. 做 1 组改前改后对比：主操作更清楚、页面更干净  

### 6.7 入门阶段先不用深挖的

- 复杂插画体系与三维动效（非岗位起步必需）
- 大型跨品牌设计系统治理
- 纯广告/平面审美堆砌（和产品 UI 目标不同）
- 只收藏灵感、不临摹、不沉淀规范

## 7. 持续学习：进阶书与长期输入

### 7.1 进阶精读（有项目后再读）

| 书名 | 作者 | 读它解决什么 |
|------|------|--------------|
| 《设计体系（Design Systems）》 | Alla Kholmatova | 从单页美观走向可复用系统 |
| 《平面设计中的网格系统》 | Josef Müller-Brockmann | 强化结构感与专业排版 |
| 《情感化设计》 | Don Norman | 理解视觉如何影响信任与品牌感知 |
| 平台与设计系统文档深读 | Material、Apple HIG、Ant Design、Fluent | 持续校正组件与规范常识 |
| 设计协作与评审表达相关书 | — | 提升跨角色沟通与方案说服力 |

### 7.2 持续输入渠道

- **临摹 + 复盘**：每周临摹 1～2 个优质界面，写“层级如何成立”
- **建立个人 UI Kit**：颜色、字体、间距、按钮、表单持续沉淀
- **改前改后对比**：专门练“让主操作更清楚、让页面更干净”
- **关注还原问题**：哪些规范含糊会导致研发做错，反向修规范
- **看优秀上线产品**：Dribbble/Behance 可启发，最终以可上线产品为准

### 7.3 建议学习顺序

1. 入门必读 4 本 + 完成 6.6 练习  
2. 有多页项目后再读网格系统与 Design Systems  
3. 再补情感化设计与平台规范深读  

---

## 8. 适合什么样的人

更适合你，如果你喜欢：

- 把界面做精致、统一、有气质
- 研究字体、色彩、留白、细节完成度
- 通过视觉手段提升信任感与操作效率
- 建立可复用的设计系统

不太适合只想画海报、不愿处理多状态与工程落地约束的人。

---

## 9. 一句话总结

**UI视觉设计师不是“把界面画好看的人”，而是“用视觉层级、风格系统与细节品质，让产品更清晰、更可信、更一致的人”。**
