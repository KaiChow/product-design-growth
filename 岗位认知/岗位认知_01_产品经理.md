# 岗位认知｜产品经理（PM）

> **定位**：决定做什么、为什么做、做成什么样算成功。  
> **核心职责**：对产品价值、范围边界与业务结果负责。  
> **协作对象**：交互设计师、视觉设计师、研发、运营、业务方。

---

## 1. 这个岗位到底做什么

产品经理管的是「价值与边界」，不是像素细节，也不是视觉风格。

深入看，日常工作通常覆盖：

- **发现机会**：识别用户痛点、业务目标、市场机会
- **定义需求**：明确功能范围、优先级、验收标准
- **权衡取舍**：在时间、成本、体验、商业目标之间做决策
- **推动落地**：对齐设计、开发、运营，跟进上线与结果复盘

常见产出：

- 需求文档 / PRD
- 用户故事与验收标准
- 业务流程图、功能优先级表
- 指标定义与结果复盘

**能力重心**：商业判断、用户洞察、沟通推进、逻辑拆解。  
**不是重点**：像素级视觉、组件规范细节、交互微动效打磨。

一句话：**决定方向和取舍，对结果负责。**

---

## 2. 与相邻岗位的边界

以「电商下单」为例：

| 角色 | 关注点 |
|------|--------|
| 产品经理 | 要不要做「一键下单」？目标是提升转化还是提升客单价？ |
| 交互设计师 | 地址、优惠券、支付方式怎么排；缺货/支付失败怎么走 |
| 视觉设计师 | 价格是否突出、主按钮是否够强、页面是否干净可信 |

协作顺序通常是：

**产品定目标与范围 → 交互定流程与结构 → 视觉定样式与品质 → 开发实现 → 数据验证。**

小团队中，产品经理有时会兼一部分交互判断，但职责边界仍应清楚：产品对「值不值得做」负责，不对「按钮圆角」负责。

## 3. 能力模型

### 3.1 必备能力

1. **问题定义**  
   能把模糊诉求拆成：用户是谁、场景是什么、要解决什么、不做什么。

2. **优先级判断**  
   能用价值、成本、风险、依赖关系排序，而不是按“感觉重要”排。

3. **需求表达**  
   能写清目标、流程、规则、边界、验收标准，让设计与研发能直接开工。

4. **沟通推进**  
   能对齐多方利益，推动决策落地，跟踪阻塞点并闭环。

5. **结果意识**  
   能定义指标（转化、留存、效率、满意度等），上线后用数据复盘。

### 3.2 进阶能力

- 商业模式与增长逻辑
- 竞品拆解与市场判断
- 实验设计（A/B、灰度）
- 跨团队影响力与资源协调
- 对设计与技术约束的基本理解（知道什么难、什么贵、什么会伤体验）

### 3.3 常见短板

- 只会写功能清单，不会写问题与目标
- 需求无限膨胀，不会砍范围
- 过度干预视觉细节，忽略业务结果
- 上线即结束，不做复盘

## 4. 作品集要求（求职/转岗）

作品集不拼“界面有多好看”，而要证明你能把事情想清楚并推动落地。

每个案例建议包含：

1. **背景与目标**：为什么做、成功标准是什么  
2. **用户与场景**：服务谁、在什么情况下用  
3. **问题拆解**：核心矛盾、限制条件、关键假设  
4. **方案与取舍**：做了什么、没做什么、为什么  
5. **落地过程**：如何推动设计/研发/运营协作  
6. **结果与复盘**：指标变化、失败点、下一步

建议准备 **2～3 个完整案例**：

- 至少 1 个有明确结果（数据、效率、转化、投诉下降等）
- 至少 1 个体现艰难取舍（资源不够、冲突目标、技术限制）
- 避免只放截图和功能列表

评审方最想看到的不是“你做过很多功能”，而是：

**你是否能定义正确问题，并在约束下做出可执行决策。**

## 5. 入门学习路径

### 阶段 A：建立基本功（2～4 周）

- 学会写：目标、用户、场景、流程、规则、验收
- 练习把一个模糊需求压成可上线的最小版本（MVP）
- 学会画简单业务流程图与信息结构

### 阶段 B：形成判断力（1～2 个月）

- 每周拆 1 个真实产品：它服务谁、核心路径是什么、指标可能是什么
- 练习优先级：同一需求给出“现在做 / 以后做 / 不做”的理由
- 学习基础数据解读：转化漏斗、留存、活跃、完成率

### 阶段 C：能独立推进（持续）

- 完整跟进一个功能：从需求到上线到复盘
- 练习跨角色协作：给交互提结构约束，给视觉提层级目标，给研发提验收标准
- 建立个人方法论：需求模板、评审清单、复盘模板

### 阶段建议产出

- 1 份标准 PRD 模板（你自己能反复用）
- 3 个竞品/产品拆解笔记
- 1 个从 0 到 1 或从 1 到 N 的完整项目复盘

## 6. 入门需要的基础知识与技能

入门不要求成为专家，但下面这些是「能开始干活」的底线。

### 6.1 基础知识

| 类别 | 要掌握到什么程度 |
|------|------------------|
| 产品基础概念 | 懂用户、场景、需求、MVP、优先级、验收标准 |
| 业务流程 | 能画简单流程图：开始、步骤、分支、结束、异常 |
| 互联网业务常识 | 知道转化、留存、活跃、漏斗；懂 C 端/B 端差异 |
| 设计协作常识 | 知道线框、原型、高保真分别解决什么问题 |
| 研发协作常识 | 懂需求评审、排期、联调、上线、回滚的基本节奏 |
| 数据常识 | 会看基础指标；知道相关不等于因果 |
| 文档表达 | 能把目标、范围、规则、边界写清楚，别人能照做 |

### 6.2 入门技能清单

- **需求分析**：把“我想要一个xx”翻译成可验证的问题与方案
- **范围控制**：能砍出最小可上线版本
- **优先级排序**：会用价值/成本/风险做取舍，并说清理由
- **PRD 写作**：目标、流程、规则、异常、验收五件套齐全
- **竞品拆解**：不只截图，要拆目标用户、核心路径、差异点
- **会议推进**：需求评审、方案对齐、阻塞跟进、结论沉淀
- **基础工具**：飞书/Notion/语雀文档；FigJam/ProcessOn 流程图；Excel/表格做优先级与数据；Axure/Figma 看懂原型即可

### 6.3 入门必读书（先读完再谈进阶）

入门阶段只要求读透下面这些，不求多。

| 优先级 | 书名 | 作者 | 为什么必读 | 怎么读 |
|--------|------|------|------------|--------|
| 必读 1 | 《人人都是产品经理》 | 苏杰 | 中文语境最快建立岗位地图 | 通读，整理自己的需求模板 |
| 必读 2 | 《用户体验要素》 | Jesse James Garrett | 建立战略→范围→结构→框架→表现分层 | 精读，能用五层拆一个产品 |
| 必读 3 | 《启示录：打造用户喜爱的产品》 | Marty Cagan | 理解现代 PM 职责与协作方式 | 精读，对照自己是否在“写需求”还是“做发现” |
| 必读 4 | 《精益创业》 | Eric Ries | 建立假设验证与 MVP 思维 | 精读方法，不背概念 |
| 选读 | 《决策与判断》或《思考，快与慢》 | 普劳斯 / 卡尼曼 | 减少拍脑袋 | 有项目后再读，边做边对照 |

**入门最低标准**：前 4 本读完，并能用其中方法独立写 1 份完整 PRD + 1 次产品拆解。

### 6.4 入门必会工具

| 用途 | 工具 | 入门要会什么 |
|------|------|--------------|
| 文档 | 飞书 / Notion / 语雀 / Word | 写 PRD、纪要、复盘 |
| 流程 | FigJam / ProcessOn / draw.io | 画业务流、任务流 |
| 表格 | Excel / 飞书表格 | 做优先级、需求池、简单数据 |
| 原型协作 | Figma / Axure（看懂即可） | 能读原型、提修改点 |
| 沟通 | 飞书/企微/邮件 | 对齐结论、跟踪待办 |

### 6.5 入门必看资源（非书）

- 公司或团队已有 PRD 模板、评审清单（有则优先学）
- 1～2 个头部产品的公开拆解文章（学习如何写，不抄结论）
- 基础数据看板说明：PV/UV、转化、留存、漏斗
- 设计侧线框/原型示例：知道自己该给设计提供什么输入

### 6.6 入门必做练习

1. 写 1 份完整 PRD（含目标、流程、规则、异常、验收）  
2. 拆 3 个真实产品（用户、主路径、商业模式、指标）  
3. 同一需求给出「现在做 / 以后做 / 不做」并说明理由  
4. 跟完 1 个小需求全流程：评审 → 设计 → 开发 → 上线 → 复盘  

### 6.7 入门阶段先不用深挖的

- 高阶增长模型、复杂商业融资逻辑
- 像素级视觉规范与组件库建设
- 自己写完整前后端代码（理解边界即可）
- 一次囤积十几本进阶书却不做项目

## 7. 持续学习：进阶书与长期输入

### 7.1 进阶精读（有实践后再读）

| 书名 | 作者 | 读它解决什么 |
|------|------|--------------|
| 《EMPOWERED》 | Marty Cagan | 产品团队运作、赋能型组织 |
| 《增长黑客》 | Sean Ellis 等 | 增长实验、北极星指标、漏斗优化 |
| 《商业模式新生代》 | Alexander Osterwalder | 商业模式画布与价值主张 |
| 《关键对话》 | Kerry Patterson 等 | 高压协作中的沟通与推动 |
| 数据化运营实务书 / 公司内部数据手册 | — | 用数据提问题和做复盘 |

### 7.2 持续输入渠道

- **每周拆 1 个产品**：目标用户、主路径、商业模式、关键指标
- **跟完整项目复盘**：需求为什么改、上线后指标如何、下次怎么改
- **读平台规范与行业报告**：了解约束与趋势，不追每一波热点名词
- **建立个人模板库**：PRD、评审清单、优先级表、复盘模板持续迭代

### 7.3 建议学习顺序

1. 入门必读 4 本 + 完成 6.6 练习  
2. 边做项目边读判断/沟通类书  
3. 有线上结果后再读增长与商业模式  

---

## 8. 适合什么样的人

更适合你，如果你喜欢：

- 想「值不值得做、先做哪个」
- 在不确定里做决策
- 跟人沟通、对齐、推动事情发生
- 用结果验证对错，而不是只追求表达完美

不太适合长期只做执行细节、不愿承担取舍责任的人。

---

## 9. 一句话总结

**产品经理不是“提需求的人”，而是“对价值负责、在约束中做取舍、把正确的事推进上线并验证结果的人”。**
